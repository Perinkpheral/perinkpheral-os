## Findings outside catalog capability checks

The Qwen reports also identify unreadable simulator mocks falling through to live HTTP,
a simulator worker/main logging race, stale plugin bundles missing the map API, and
ineffective audit harnesses/baselines. Those are tools/plugin/test-quality defects,
not an application's SDK behavior. Existing dedicated tests address them; compiling an
application against `sdk/check` cannot validate the simulator's network thread or a
plugin distribution. Memory-reduction and shared-helper proposals in the audits are
not automatically correctness defects.

## Interpreting catalog results

The companion catalog result records the read-only run, repository commit, exact command,
failures by application and coverage notes. Default malformed-response checks deliberately
use a strict oracle. An optional-field fallback or valid empty list may produce another
correct picture: declare the narrow `responses.*` exception with a reason and keep that
behavior in the application's own tests. A failure is a reproducible invariant mismatch
under the listed inputs, not a claim that every changed picture is semantically wrong.
